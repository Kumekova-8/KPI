# Архитектура и API KPI КГД

## Контуры

Приложение обслуживает интерфейс и REST API с одного локального адреса. Интерфейс использует JavaScript-модули и словари русскоязычных подписей. Добавление казахской локализации требует выделить оставшиеся подписи форм и подготовить перевод справочника. Сервер использует стандартный HTTP-обработчик Python. Это позволяет запускаться в комплектном Windows Python при недоступной установке пакетов FastAPI, React и TypeScript. API импорта использует openpyxl, а экспорт PDF — ReportLab. PostgreSQL доступен через psycopg в Compose, SQLite служит локальным вариантом для запуска из каталога.

| Модуль | Где находится | Ответственность |
|---|---|---|
| HTTP и доступ | `kpi/server.py`, `kpi/security.py` | Маршруты, валидация, серверные сессии, ограничения ролей и областей |
| Процесс | `kpi/workflow.py` | Пакеты, проверка, редакции, дедлайны, результаты и рейтинги |
| Методика | `kpi/methodology.py`, `kpi/rules.py` | Весовая иерархия, допустимая арифметика, шкалы, периоды и публикации |
| Раздел источников | `kpi/integrations.py` | Контракты коннекторов и верификатора подписи, синтетический адаптер |
| Обмен | `kpi/exchange.py` | Поля импорта, формирование Excel и PDF |
| База | `kpi/db.py`, `migrations/*.sql` | Миграции, транзакции, адаптеры PostgreSQL и SQLite |

## Модель данных

| Сущность | Связи и срок хранения |
|---|---|
| `users`, `sessions` | Роль и область доступа закреплены за пользователем. Временные сессии с хешированными токенами |
| `regions` | Каталог ДГД и ЦТЛ |
| `methods` | Версионные снимки структуры индикатор → показатель → субкомпонент, полей, источников и шкал. Запись утверждающего, родительская версия и дата действия |
| `periods` | Закрепление опубликованной методики за контуром, месяцем и видом отчётности при создании первого пакета |
| `packages` | Организация, ответственное подразделение, период, версия методики и редакция. Данные и замечания хранятся вместе с подписанной редакцией |
| `attachments` | Подтверждающие вложения, тип, размер и SHA-256. Включаются в подписываемый манифест |
| `deputies` | Назначение с датой начала и окончания. Связь `person` связывает назначения одного заместителя через историю |
| `results` | Неизменяемые снимки итогов и использованных редакций пакетов. При новой редакции прежний снимок остаётся доступен |
| `settings`, `audit` | Перенос установленных сроков с основанием, кто и когда выполнил действие |

Типовой путь пакета — черновик → подан → проверен → подписан. Проверяющий может вернуть отдельные строки с замечанием. В повторной редакции прежний подписанный набор и расчёт сохраняются. Атомарная публикация результата происходит в той же транзакции, что и подписывание последнего обязательного пакета. Редактирование сверяет `generation` с последней версией, конфликт возвращает HTTP 409. Запись сериализуется на SQLite и через транзакционную блокировку в PostgreSQL.

## REST API

Все защищённые маршруты читают роль на сервере. Для витрин и пакетов параметры `track=demo|source`, `period=ГГГГ-ММ`, `kind=month|quarter|year` определяют контур и период. Квартал задаётся завершающим месяцем, год декабрём.

| Метод и путь | Доступ и результат |
|---|---|
| GET `/api/health` | Техническая доступность HTTP |
| POST `/api/login`, GET `/api/me`, POST `/api/logout` | Вход с `username`, `password`, проверка и завершение сессии |
| GET, POST `/api/packages` | Перечень по области доступа. Создание черновика сотрудником ДГД или ЦТЛ с `department` |
| GET `/api/packages/{id}` | Карточка, расчёт, комментарии, журнал, версия и файлы |
| POST `/api/packages/{id}/{action}` | Действия `save`, `submit`, `return`, `check`, `sign`, `revise`, `prefill`. Передаётся `generation` и поля действия |
| POST `/api/packages/{id}/attachment` | Тело файла, в запросе `name`, `code`, `generation`. GET и DELETE через `/attachment/{file_id}` |
| GET `/api/packages/{id}/signature` | Канонический пакет и метаданные демонстрационной подписи |
| GET `/api/packages/{id}/template.xlsx`, POST `/api/packages/{id}/import` | Шаблон и проверка книги. Параметр `apply=1` вносит проверенные значения |
| GET `/api/dashboard`, GET `/api/report` | Сводка УСР, карточка региона. `region` задаёт организацию, `revision` выбирает сохранённый снимок |
| GET `/api/export.xlsx`, GET `/api/export.pdf` | Сводный отчёт либо карточка с `region`. PDF принимает также `deputy` |
| GET, POST `/api/methods` | Список версий и создание версии с `parent`, `name`, `reason`, `effective` |
| GET `/api/methods/{id}[/diff\|/history]` | Содержимое, сравнение с родительской версией и события |
| PUT `/api/methods/{id}/entry` | Добавление, исключение или изменение субкомпонента с `original` и `entry` |
| PUT `/api/methods/{id}/aggregate` | Регистрация решения по итоговой агрегации в черновике, для ЦТЛ указывается знаменатель |
| POST `/api/methods/{id}/{action}` | `preview`, `submit`, `approve`, `send_back`, `publish` |
| GET `/api/discrepancies` | Реестр с адресами источников |
| GET, POST `/api/deputies` | Реестр назначений и новое назначение, при смене указывается `previous` |
| GET `/api/deputies/{id}/results` | История подтверждённых результатов заместителя |
| GET, PUT `/api/calendar` | Сроки, перенос с указанием основания |
| GET `/api/technical`, POST `/api/technical/users` | Сводка, состояние интеграций, журнал действий, создание и включение или отключение демонстрационных учетных записей |

Пример сохранения для одной строки пакета:

```json
{"generation":0,"facts":{"S001":{"A":"105","B":"100"}}}
```

## Подключения и согласования

- **НУЦ РК и NCALayer.** Интерфейс верификатора ждёт байты канонического документа и CMS. Для промышленного режима нужны доверенная тестовая среда, аутентификация сертификата и сопоставление его владельца с полномочиями, серверная проверка CMS, цепочки, отзыва и целостности. Демонстрационная подпись хранит SHA-256, пользователя и время, юридического статуса у неё нет.
- **SDF, ИСНА, Кеден, ИС ЭСФ и другие системы.** Нужны согласованные контракты данных, доступ в тестовые среды и проверяемое происхождение входных полей. Синтетический адаптер иллюстрирует передачу исходных полей и метаданных. Отбор детальных записей, исключения и дедупликация из приложения 2 выполняются поставщиком входных агрегатов или будущим коннектором.
- **Методология.** Требуются подписанные реквизиты приказа, периодные планы и правила по реестру. Для решений по целям и агрегации предусмотрены запись основания и независимое утверждение новой версии. Смена правил для уже закреплённого периода требует отдельного согласованного процесса. В прототипе доступна корректировка фактов по прежней закреплённой методике.
- **Календарь.** Базовые 5, 10 и 15 числа формируются сервером. Прототип показывает уведомления в кабинете и допускает установленный вручную перенос с основанием. Праздничный календарь и регламент автоматических переносов требуют решения КГД.
- **Эксплуатация.** Нужны утверждённые схема размещения, TLS, централизованные учётные записи и MFA, защищённое хранилище, проверка вложений, мониторинг с внешним журналом и регламент восстановления. Прототип проверяет права, изолирует данные по подразделениям, фиксирует изменения и поддерживает локальную копию и восстановление. Серверная сессия становится Secure при `KPI_SECURE_COOKIE=1` для HTTPS.
