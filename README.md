# KPI КГД

Локальный работающий прототип отчётности и аналитики для 20 территориальных ДГД, Центральной таможенной лаборатории и заместителей руководителей. Все сведения, профили сотрудников, подтверждения и результаты в базе синтетические. Внешние подключения отсутствуют.

## Запуск на Windows

Откройте `run-local.cmd`, дождитесь строки `Local` и перейдите по адресу [127.0.0.1:8765](http://127.0.0.1:8765). Окно запуска должно оставаться открытым. Скрипт использует Python из среды Codex, если он установлен, или `python` из PATH. При первом запуске миграция создаёт базу `runtime/kpi.sqlite3`, затем заполняется демонстрационная история с мая по октябрь 2026 года.

Для установки на другом компьютере из каталога проекта:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m kpi.server
```

Для Linux используйте `.venv/bin/python`. Базу можно указать переменной `KPI_DATABASE`. Порт можно изменить, добавив `--port 8766`.

## Docker Compose

```text
docker compose up --build
```

Compose поднимает веб-приложение и PostgreSQL 16, запускает миграции и хранит данные в томе `kpi-db`. Адрес интерфейса тот же. Порт опубликован на loopback. Конфигурация предназначена для демонстрационных данных. В этой Windows-среде Docker CLI не установлен, поэтому Compose и выполнение SQL в PostgreSQL требуют отдельного прогона.

## Демонстрационные кабинеты

На форме входа есть кнопки для входа под перечисленными учётными записями. Общий демонстрационный пароль **`Kpi-demo-26!`**.

| Логин | Полномочия |
|---|---|
| `dgd` | Ввод сведений ДГД Абайской области |
| `dgd-astana` | Ввод сведений ДГД г. Астаны |
| `ctl` | Ввод сведений ЦТЛ |
| `reviewer-dasur` | Проверка пакетов ДАСУР и возврат строк |
| `signer-dasur` | Демонстрационное подписание проверенных пакетов ДАСУР |
| `analyst` | Панель УСР, рейтинги, календарь и экспорт |
| `method` | Создание версий, конструктор правил, назначения заместителей и перенос сроков |
| `approval` | Независимое утверждение методики |
| `tech` | Управление доступом и журнал действий |

Другие тестовые подразделения используют пары `reviewer-<код>` и `signer-<код>`. Коды `dna`, `audit`, `dta`, `personnel`, `service`, `fl`, `dtk`, `debts`, `dkn`, `training` соответствуют справочнику в `kpi/seed.py`.

## Сценарий демонстрации

1. Войдите как `dgd`. В кабинете за октябрь 2026 года откройте черновик ДАСУР. Введите, например, факт 105 и план 100, сохраните и направьте пакет на проверку.
2. Войдите как `reviewer-dasur`. Найдите Абайскую область. Введите замечание у строки и нажмите «Вернуть отмеченные строки».
3. Войдите снова как `dgd`, откройте возвращённый пакет, измените факт на 103 и отправьте повторно. Как проверяющий подтвердите проверку пакета.
4. Войдите как `signer-dasur` и нажмите «Демонстрационная подпись». После этого в карточке пакета доступны подпись, журнал и загрузка подписанной редакции.
5. Войдите как `analyst`. Откройте Абайскую область в рейтинге. УСР видит автоматически рассчитанный итог и может скачать сводный Excel или PDF.
6. Как `method` создайте черновик из демонстрационной версии с датой действия 2026-11 или позже. Измените верхний порог S001 со 100 до 105. В контрольном расчёте факт 103 и план 100 дадут 90 баллов. Сохраните правило, сравните версии и направьте черновик на утверждение.
7. Войдите как `approval`, утвердите версию. Как `method` опубликуйте её. Октябрьская карточка продолжит показывать ранее зафиксированную версию. Новая применяется к ещё не закреплённым периодам с установленной даты.
8. Для корректировки подписанных данных откройте пакет как `dgd` и создайте редакцию с основанием. После её подписания результат получает новый номер редакции и сохраняет историю. Закреплённая методика периода используется и для корректировки.

Для возврата к чистым учебным данным запустите сервер с новым путём базы в `KPI_DATABASE`. Существующая база останется доступна по прежнему пути.

## Источники и расчёты

Конструктор содержит исходный справочник из 14 индикаторов, 29 показателей, 88 субкомпонентов и 5 функциональных блоков. Нормативный статус проверяется по подписанным реквизитам, которых в предоставленной редакции нет. Зафиксированы тексты правил, веса, периоды, источники, ответственные и Excel-формулы со всех листов. Данные книги Excel не загружаются как фактические сведения в демонстрационную базу.

В контуре «Исходные документы» оценки по спорным правилам блокируются со статусом «Требуется уточнение методики». Приложение не переносит баллы на спорные интервалы и не подставляет универсальную шкалу вместо приложения 2. Для разбора расхождений открывайте реестр в УСР или конструкторе. Документы по анализу находятся в каталоге `docs`.

Демонстрационная методика использует восемь учебных правил с собственными порогами, назначениями и весами. Она позволяет проверить весь цикл до рейтинга. Вес индикатора и показателей из расчётной формы передаётся в реестр, баллы рассчитываются иерархически. В контуре исходных материалов для ДГД удерживается итог по п. 24 до разрешения применимости, переноса периодов и реквизитов. Для ЦТЛ требуется установить знаменатель п. 25. По п. 26 реализовано отношение фактических баллов закреплённых субкомпонентов к их базовым баллам, с выбором назначения на конец периода в демонстрации.

## Excel и PDF

Откройте пакет и скачайте «Шаблон Excel». Заполните колонку «Значение» листа «Ввод», сохраните книгу и выберите «Импорт Excel». Проверка показывает, сколько строк можно применить, и перечисляет ошибки. Для исходного контура историческая форма сопоставляется по номеру, импортирует только самостоятельные числовые входы и помечает агрегаты, требующие числителя и знаменателя.

Экспорт УСР содержит сводку, расчётную форму, заместителей и реквизиты. PDF формируется с кириллицей и доступен для общего отчёта и карточек. Полные формулы книги и их адреса сохранены в `data/catalog.json` для сверки.

## Проверки и резервное копирование

```text
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

Тесты используют отдельную базу и настоящий обработчик HTTP. Для прогона через TCP добавьте `KPI_TEST_LIVE=1`. Для прогона на отдельной чистой тестовой PostgreSQL установите psycopg и задайте `KPI_TEST_DATABASE` со строкой подключения.

Для SQLite:

```text
python tools/backup_sqlite.py runtime/kpi.sqlite3 runtime/backup-2026-11-16.sqlite3
```

Чтобы проверить восстановление, укажите файл копии в `KPI_DATABASE` и запустите отдельный экземпляр. Для PostgreSQL используйте `pg_dump -Fc` и `pg_restore` в отдельную базу. Плановое резервирование, ротация и контроль восстановления зависят от инфраструктуры размещения.
